# 노드 체크포인트와 이어서 하기

전투 옵션의 `타이틀로 돌아가기`는 프로그램을 종료하지 않습니다. 확인 후 타이틀로 이동하고, 유효한 진행 파일이 있으면 타이틀의 `이어서 하기` 버튼이 표시됩니다. 타이틀의 `게임 시작`은 [캐릭터 선택 창](TitleMenu.md#캐릭터-선택)을 엽니다. 군인을 선택한 뒤 `모험 시작`을 확정하면 새 체크포인트를 저장하며, 선택 창에서 뒤로 돌아가면 기존 저장을 유지합니다. `이어서 하기`는 캐릭터 선택을 건너뛰며, `게임 종료`는 프로그램을 종료합니다.

## 저장 기준

| 시점 | 저장 결과 |
|---|---|
| 모험 시작 확정·맵 노드 입장 | 맵 생성 정보, 노드 선택 상태, 체력, 덱, 골드, 매개체 저장 |
| 전투 중 타이틀 복귀 | 전투 입장 체크포인트 유지. 전투 중 피해·손패·일시 효과는 저장하지 않음 |
| 전투 승리 | 전투 후 체력과 보상 단계 저장. 이어하기에서 전투를 반복하지 않고 보상창 재개 |
| 골드·카드 수령 | 소유 자원과 수령 여부를 함께 저장 |
| 보상 덱 선택 | 확정된 후보와 선택 단계를 저장하여 재추첨 방지 |
| 상점 입장 후 진열 확정 | 꿈·악몽 카드와 슬롯 순서를 노드 상태에 저장 |
| 상점 카드 구매 | 차감한 골드, 추가한 카드와 슬롯 품절을 함께 저장. 실패하면 세 상태를 복구 |
| 상점 나가기 | 다음 맵 진행 상태 저장. 실패하면 상점 유지 |
| 휴식 체력 회복 | 회복 후 HP와 다음 맵 진행을 함께 저장. 실패하면 기존 HP와 휴식 화면 유지 |
| 전투 보상 완료 | 다음 맵 진행 상태 저장 |
| 런 완료·패배·전투 취소 | 이어하기 무효화 후 파일 정리 |

전투 입장 시 꿈·악몽 초기 덱 섞기는 노드별 시드로 재현합니다. 공용 안개가 화면을 가린 동안 BattleScene이 적과 초기 인벤토리를 구성하고 전투 입장 체크포인트를 확정합니다. 전투 진행 도중 상태 전체를 저장하는 기능은 아닙니다.

저장 파일은 `Application.persistentDataPath/run-checkpoint.json`입니다. 임시 파일을 기록한 후 기존 파일을 교체하므로 진행 단계와 소유 자원이 하나의 파일에 함께 확정됩니다. 손상된 파일, 지원하지 않는 버전, 누락된 카드·매개체·런 데이터는 이어하기로 표시하지 않습니다.

종료된 런은 `.ended` 표시를 먼저 기록합니다. 기존 파일이 잠겨 삭제되지 않더라도 이후 실행에서 해당 파일을 이어하기로 읽지 않습니다. 새 게임 저장이 성공하면 이 표시를 제거합니다.

## 비전투 노드 연결

- **상점**에서 이어서 하면 패널을 바로 열고 진열 순서, 품절 슬롯, 보유 골드와 런 덱을 복원합니다. 가격은 저장된 진열과 노드 시드로 재현합니다. 품절 여부가 없는 이전 진열 기록은 재고가 있는 상태로 읽고, 진열 기록 자체가 없으면 해당 노드 시드로 상품을 뽑습니다. 구매와 나가기 저장에 실패하면 상점에서 다시 시도할 수 있습니다.
- **휴식**에서 이어서 하면 저장된 현재 HP로 패널을 바로 엽니다. 체력 회복을 누르면 `RunSession.CompleteRest`가 회복 후 HP와 노드 완료를 한 번에 확정합니다. 저장에 실패하면 회복과 완료를 함께 되돌리며, 성공한 뒤에는 같은 휴식에서 회복을 다시 받을 수 없습니다.
- 이미 생성된 맵은 저장된 선택지를 복원합니다. 상점·휴식 배치 변경은 새로 생성하는 맵에 적용됩니다.

상점은 진열과 품절 상태, 구매 결과와 퇴장을 저장합니다. 카드 구매는 아래 획득 처리 계약을 사용하며, 카드 제거·강화와 매개체 획득에도 같은 계약을 사용할 수 있습니다.

- `MapContentHandler.Begin`: 노드 UI를 준비합니다. 노드별 난수에는 `progress.NodeSeed`를 사용합니다. 이 함수에서 구매·보상 지급 같은 확정 효과를 실행하지 않습니다.
- `CaptureState()`: 고정 상품·후보 목록, 재고, 수령 기록을 저장 가능한 JSON 문자열로 반환합니다.
- `RestoreState(string)`: UI를 재구성하고 저장된 상품·후보·재고·수령 기록을 복원합니다. 소유 자원은 이미 복원되어 있으므로 다시 지급하지 않습니다.
- `CaptureVisit(progress)`: 입장 시 한 번 호출해 해당 노드 방문을 보관합니다. 버튼 등의 콜백은 이 방문 객체를 캡처해야 하며, 실행 시점의 변경된 `progress`에서 노드 번호를 다시 읽지 않습니다.
- `CommitAcquisition(visit, Action)`: 구매·획득 전체를 하나의 작업으로 실행합니다. 골드 차감, 카드·매개체 획득, 재고·수령 기록 변경을 Action 안에서 모두 수행합니다. 성공할 때만 true이며, 저장 실패 시 소유 자원과 핸들러 상태를 되돌립니다. 이전 방문의 지연 콜백은 거부합니다.
- 입장을 완료한 직후와 이어하기에서 MapController가 위 함수를 연결합니다. 노드 완료 콜백은 거래 Action과 분리하여 완료가 확정된 뒤 호출합니다.

게임 진행 중 생성·강화하는 카드도 저장 카탈로그에서 찾을 수 있는 에셋 ID가 필요합니다. 카드 이름이나 실행 중 InstanceID는 저장 키로 사용하지 않습니다.

## 에셋 목록과 검증

`Assets/Resources/RunAssetCatalog.asset`은 에셋 GUID와 로컬 ID를 런·카드·덱·매개체·전투·노드 데이터 참조에 연결합니다. 관련 `.asset` 변경 시 목록을 갱신하며 빌드 전에도 갱신합니다. 수동 메뉴는 `ProjectDN/Refresh Run Save Catalog`입니다. `ProjectDN/Setup Run Checkpoints`는 기존 타이틀·전투 씬에 버튼과 문구를 연결합니다.

테스트 실행에서는 `PROJECTDN_RUN_SAVE_PATH`로 `.utmp/run-save` 아래 별도 파일을 사용하여 실제 사용자 저장 파일에 접근하지 않습니다.

Unity 6000.0.85f2에서 상점·휴식 복원, 저장 실패 후 재시도, 회복한 HP의 다음 전투 반영을 확인했습니다. 2026-11-11에는 카드 구매 저장 실패 후 골드·덱·재고 복구, 구매 후 이어서 하기의 품절과 가격 복원도 검사했습니다. 결과는 [맵 검증](MapSystem.md#검증)에 정리했습니다.
