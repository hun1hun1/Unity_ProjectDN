# 노드 체크포인트와 이어서 하기

맵·전투 옵션의 `타이틀로 돌아가기`를 확인하면 최근 체크포인트를 유지한 채 타이틀로 이동합니다. 유효한 진행 파일이 있으면 타이틀에 `이어서 하기` 버튼이 표시됩니다. 타이틀의 `게임 시작`은 [캐릭터 선택 창](TitleMenu.md#캐릭터-선택)을 엽니다. 군인을 선택한 뒤 `모험 시작`을 확정하면 새 체크포인트를 저장하며, 선택 창에서 뒤로 돌아가면 기존 저장을 유지합니다. `이어서 하기`는 캐릭터 선택을 건너뛰며, `게임 종료`는 프로그램을 종료합니다.

## 저장 기준

| 시점 | 저장 결과 |
|---|---|
| 모험 시작 확정·맵 노드 입장 | 맵 진행, 체력, 덱, 골드, 매개체 저장. 군인의 첫 체크포인트에 탄피를 포함하며, 1층 전투 진입 시 확정한 조우도 저장 |
| 전투 중 타이틀 복귀 | 전투 입장 체크포인트 유지. 전투 중 피해·손패·일시 효과는 저장하지 않음 |
| 전투 승리 | 응급 붕대의 승리 회복을 반영한 체력과 보상 단계 저장. 이어하기에서 저장된 체력으로 보상창 재개 |
| 골드·카드 수령 | 소유 자원과 수령 여부를 함께 저장 |
| 보상 덱 선택 | 확정된 후보와 선택 단계를 저장하여 재추첨 방지 |
| 미지 선택 | 원본 선택지 인덱스와 확정된 결과 유형·전투 또는 콘텐츠 에셋 ID를 함께 저장 |
| 미지 이벤트·매개체 노드 이용 | 골드 또는 매개체 획득과 노드 완료를 함께 저장. 지나가기를 선택하면 노드 완료만 저장 |
| 상점 입장 후 진열 확정 | 꿈·악몽 카드와 슬롯 순서를 노드 상태에 저장 |
| 상점 카드 구매 | 차감한 골드, 추가한 카드와 슬롯 품절을 함께 저장. 실패하면 세 상태를 복구 |
| 상점 카드 제거 | 차감한 골드, 선택한 카드를 제거한 덱, 런의 누적 제거 횟수를 함께 저장. 실패하면 세 상태를 복구 |
| 상점 나가기 | 다음 맵 진행 상태 저장. 실패하면 상점 유지 |
| 휴식 체력 회복 | 회복 후 HP와 다음 맵 진행을 함께 저장. 실패하면 기존 HP와 휴식 화면 유지 |
| 휴식 카드 강화 | 선택한 덱 항목 교체와 다음 맵 진행을 함께 저장. 실패하면 원래 카드와 휴식 진행을 복구하고 비교 화면 유지 |
| 전투 보상 완료 | 다음 맵 진행 상태 저장. 엘리트의 직접 매개체 보상도 함께 저장하며, 실패하면 지급과 노드 진행을 복구 |
| 런 완료·패배·전투 취소 | 이어하기 무효화 후 파일 정리 |

전투 입장 시 꿈·악몽 초기 덱 섞기는 노드별 시드로 재현합니다. 공용 안개가 화면을 가린 동안 BattleScene이 적과 초기 인벤토리를 구성하고 전투 입장 체크포인트를 확정합니다. 전투 진행 도중 상태 전체를 저장하는 기능은 아닙니다.

저장 파일은 `Application.persistentDataPath/run-checkpoint.json`입니다. 임시 파일을 기록한 후 기존 파일을 교체하므로 진행 단계와 소유 자원이 하나의 파일에 함께 확정됩니다. 손상된 파일, 지원하지 않는 버전, 누락된 카드·매개체·런 데이터는 이어하기로 표시하지 않습니다.

종료된 런은 `.ended` 표시를 먼저 기록합니다. 기존 파일이 잠겨 삭제되지 않더라도 이후 실행에서 해당 파일을 이어하기로 읽지 않습니다. 새 게임 저장이 성공하면 이 표시를 제거합니다. 패배 시 이 정리를 즉시 시도하며, 타이틀 복귀 때도 확인합니다. 파일 정리에 실패하면 패배 패널에서 실패를 안내하고 복귀를 다시 시도할 수 있습니다.

## 1층 조우와 매개체 복원

1층 체크포인트의 `encounterOrder`에는 전반부·후반부 일반 조우와 엘리트 조우의 순서를 기록합니다. 일반·엘리트 전투의 조우는 선택을 확정할 때 저장하고, 보스 조우는 층을 생성할 때 선택지에 기록합니다. 다음 조우 위치는 복원한 노드의 완료 기록에서 계산합니다. 미지에서 일반 전투가 나와 완료한 경우도 포함합니다. 전투 진입 저장에 실패하면 선택을 되돌리므로 재시도로 조우 순서가 추가로 진행하지 않습니다.

1층 진입 시 섞은 일반·고급 매개체 순서를 저장합니다. 획득 목록과 앞선 노드에 제시된 선택지로 사용한 후보를 확인하며, 지나친 후보도 중복 제시하지 않습니다. 엘리트 보상 지급과 다음 노드 진행은 같은 체크포인트에 기록합니다. 6번 전투를 마칠 때는 실제로 이긴 전투 유형에 맞춰 7번 매개체도 같은 저장에 확정합니다. 저장 실패 후에는 이전 보유 목록·노드·순서를 복원하므로 같은 보상으로 다시 시도할 수 있습니다. 순서 필드가 없는 이전 저장은 런 시드로 순서를 생성하고 이미 확정된 보상을 복원합니다.

보유 매개체는 획득 순서대로 에셋 ID, 최대 탄약 증가량, 전투·플레이어 턴 시작 장전량, 전투 시작 방어도, 전투 시작 버프의 에셋 ID와 수치, 승리 회복량, 휴식 추가 회복량, 꿈·악몽 손패 한도 증가량, 약점 노출 추가 턴 수, 상점 할인율, 골드 획득 증가율, 엘리트 보상 확률 보정 여부, 전투 시작 꿈 게이지 절반 충전 여부, 녹슬음 면역 여부를 기록합니다. 이전 저장에 각 효과의 필드가 없으면 해당 효과를 적용하지 않습니다. 전투 입장 체크포인트를 재개하면 보유 매개체의 전투 시작 효과를 새 전투 초기화에서 한 번 적용합니다. 유효한 5노드 임시 런 저장은 기록된 런 정의와 노드로 이어집니다. 타이틀에서 새 모험을 시작할 때 13노드 맵과 탄피가 적용됩니다. ## 비전투 노드 연결

미지 선택지는 노드 시드에서 파생한 난수로 결과를 정합니다. 원래 선택지 인덱스와 실제 결과를 함께 저장하고, 저장이 성공하면 카드 연출 뒤 결과의 씬이나 패널을 엽니다. 고정 매개체도 진입 저장 뒤 카드 연출을 재생합니다. 연출 중에는 입력을 잠그며, 이어서 하기에서는 저장된 결과 화면을 바로 엽니다. 고정 매개체 선택지도 선택지에 저장된 매개체를 그대로 표시합니다. 이벤트 골드와 매개체 획득은 다음 노드 진행과 함께 확정합니다. 저장에 실패하면 해당 결과 화면과 이전 인벤토리를 복구합니다.

- **상점**에서 이어서 하면 패널을 바로 열고 진열 순서, 품절 슬롯, 보유 골드, 런 덱, 누적 카드 제거 횟수를 복원합니다. 진열 기본가는 저장된 진열과 노드 시드로 재현하며, 제거 기본가는 `100 + 50 × 누적 제거 횟수`입니다. 복원한 매개체의 할인율을 양쪽 기본가에 적용하고 소수점 이하는 버립니다. 횟수 필드가 없는 이전 저장은 0회로 읽습니다. 품절 여부가 없는 이전 진열 기록은 재고가 있는 상태로 읽고, 진열 기록 자체가 없으면 해당 노드 시드로 상품을 뽑습니다. 구매·제거·나가기 저장에 실패하면 상점에서 다시 시도할 수 있습니다.
- **휴식**에서 이어서 하면 저장된 현재 HP로 패널을 바로 엽니다. 체력 회복을 누르면 `RunSession.CompleteRest`가 회복 후 HP와 노드 완료를 한 번에 확정합니다. 저장에 실패하면 회복과 완료를 함께 되돌리며, 성공한 뒤에는 같은 휴식에서 회복을 다시 받을 수 없습니다.
- 이미 생성된 맵은 저장된 선택지를 복원합니다. 상점·휴식 배치 변경은 새로 생성하는 맵에 적용됩니다.

- **휴식 카드 강화**는 선택한 런 덱 항목 교체와 휴식 완료를 같은 체크포인트에 기록합니다. 저장에 실패하면 원래 카드와 휴식 진행 상태를 복구하고 비교 화면에서 다시 시도할 수 있습니다. 확인 전에 종료하고 이어서 하면 휴식 선택 화면을 엽니다.

상점의 카드 구매와 제거는 같은 거래 저장 흐름을 사용합니다.

- `MapContentHandler.Begin`: 노드 UI를 준비합니다. 노드별 난수에는 `progress.NodeSeed`를 사용합니다. 이 함수에서 구매·보상 지급 같은 확정 효과를 실행하지 않습니다.
- `CaptureState()`: 고정 상품·후보 목록, 재고, 수령 기록을 저장 가능한 JSON 문자열로 반환합니다.
- `RestoreState(string)`: UI를 재구성하고 저장된 상품·후보·재고·수령 기록을 복원합니다. 소유 자원은 이미 복원되어 있으므로 다시 지급하지 않습니다.
- `CaptureVisit(progress)`: 입장 시 한 번 호출해 해당 노드 방문을 보관합니다. 버튼 등의 콜백은 이 방문 객체를 캡처해야 하며, 실행 시점의 변경된 `progress`에서 노드 번호를 다시 읽지 않습니다.
- `CommitAcquisition(visit, Action)`: 거래나 획득을 하나의 작업으로 실행합니다. 골드 차감, 카드 추가·제거 또는 매개체 획득, 해당 거래의 재고·횟수·수령 기록 변경을 Action 안에서 수행합니다. 성공할 때만 true이며, 저장 실패 시 소유 자원과 핸들러 상태를 되돌립니다. 이전 방문의 지연 콜백은 거부합니다.
- `CompleteContentWithAcquisition`: 골드 이벤트와 매개체 획득을 노드 완료와 함께 저장합니다. 실패하면 기존 진행과 인벤토리를 복구합니다. `지나가기`는 보상 지급 없이 완료만 저장합니다.
- 입장을 완료한 직후와 이어하기에서 MapController가 위 함수를 연결합니다. 상점의 거래와 노드 퇴장은 별도로 확정합니다.

게임 진행 중 생성·강화하는 카드도 저장 카탈로그에서 찾을 수 있는 에셋 ID가 필요합니다. 카드 이름이나 실행 중 InstanceID는 저장 키로 사용하지 않습니다.

## 에셋 목록과 검증

`Assets/Resources/RunAssetCatalog.asset`은 에셋 GUID와 로컬 ID를 런·카드·덱·매개체·전투·노드 데이터 참조에 연결합니다. 관련 `.asset` 변경 시 목록을 갱신하며 빌드 전에도 갱신합니다. 수동 메뉴는 `ProjectDN/Refresh Run Save Catalog`입니다. `ProjectDN/Setup Run Checkpoints`는 기존 타이틀·전투 씬에 버튼과 문구를 연결합니다.

테스트 실행에서는 `PROJECTDN_RUN_SAVE_PATH`로 `.utmp/run-save` 아래 별도 파일을 사용하여 실제 사용자 저장 파일에 접근하지 않습니다.

Unity 6000.0.85f2에서 상점·휴식 복원, 저장 실패 후 재시도, 회복한 HP의 다음 전투 반영을 확인했습니다. 2026-11-11에는 카드 구매 저장 실패 후 골드·덱·재고 복구, 구매 후 이어서 하기의 품절과 가격 복원도 검사했습니다. 결과는 [맵 검증](MapSystem.md#검증)에 정리했습니다.

13노드 조우와 시작 매개체의 테스트 범위는 [1층 검증](MapSystem.md#2026-11-17-1층-13노드와-시작-매개체)에 있습니다. 공용 보상 순서, 매개체 효과 복원과 저장 실패 후 재시도 결과는 [공용 매개체 검증](MapSystem.md#공용-매개체와-효과-검증)에 있습니다.
