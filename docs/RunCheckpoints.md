# 노드 체크포인트와 이어서 하기

전투 옵션의 `타이틀로 돌아가기`는 프로그램을 종료하지 않습니다. 확인 후 타이틀로 이동하고, 유효한 진행 파일이 있으면 타이틀의 `이어서 하기` 버튼이 표시됩니다. 타이틀의 기존 `게임 시작`은 새 진행으로 저장을 교체하며, `게임 종료`는 프로그램을 종료합니다.

## 저장 기준

| 시점 | 저장 결과 |
|---|---|
| 새 게임·맵 노드 입장 | 현재 노드 선택, 체력, 덱, 골드, 유물과 맵 생성 정보 저장 |
| 전투 중 타이틀 복귀 | 전투 입장 체크포인트 유지. 전투 중 피해·손패·일시 효과는 저장하지 않음 |
| 전투 승리 | 전투 후 체력과 보상 단계 저장. 이어하기에서 전투를 반복하지 않고 보상창 재개 |
| 골드·카드 수령 | 소유 자원과 수령 여부를 함께 저장 |
| 보상 덱 선택 | 확정된 후보와 선택 단계를 저장하여 재추첨 방지 |
| 보상 완료·노드 완료 | 다음 맵 진행 상태 저장 |
| 런 완료·패배·전투 취소 | 이어하기 무효화 후 파일 정리 |

전투 입장 시 꿈·악몽 초기 덱 섞기는 노드별 시드로 재현합니다. 전투 진행 도중 상태 전체를 저장하는 기능은 아닙니다.

저장 파일은 `Application.persistentDataPath/run-checkpoint.json`입니다. 임시 파일을 기록한 후 기존 파일을 교체하므로 진행 단계와 소유 자원이 하나의 파일에 함께 확정됩니다. 손상된 파일, 지원하지 않는 버전, 누락된 카드·유물·런 데이터는 이어하기로 표시하지 않습니다.

종료된 런은 `.ended` 표시를 먼저 기록합니다. 기존 파일이 잠겨 삭제되지 않더라도 이후 실행에서 해당 파일을 이어하기로 읽지 않습니다. 새 게임 저장이 성공하면 이 표시를 제거합니다.

## 비전투 노드 연결

현재 실제 상점·유물 노드 UI/핸들러는 없습니다. 다음 공통 계약을 구현해 연결할 수 있습니다. 저장 때문에 기존 생성 규칙이나 활성 콘텐츠를 변경하지 않았습니다.

- `MapContentHandler.Begin`: 노드 UI를 준비합니다. 노드별 난수에는 `progress.NodeSeed`를 사용합니다. 이 함수에서 구매·보상 지급 같은 확정 효과를 실행하지 않습니다.
- `CaptureState()`: 고정 상품·후보 목록, 재고, 수령 기록을 저장 가능한 JSON 문자열로 반환합니다.
- `RestoreState(string)`: UI를 재구성하고 저장된 상품·후보·재고·수령 기록을 복원합니다. 소유 자원은 이미 복원되어 있으므로 다시 지급하지 않습니다.
- `CaptureVisit(progress)`: 입장 시 한 번 호출해 해당 노드 방문을 보관합니다. 버튼 등의 콜백은 이 방문 객체를 캡처해야 하며, 실행 시점의 변경된 `progress`에서 노드 번호를 다시 읽지 않습니다.
- `CommitAcquisition(visit, Action)`: 구매·획득 전체를 하나의 작업으로 실행합니다. 골드 차감, 카드·유물 획득, 재고·수령 기록 변경을 Action 안에서 모두 수행합니다. 성공할 때만 true이며, 저장 실패 시 소유 자원과 핸들러 상태를 되돌립니다. 이전 방문의 지연 콜백은 거부합니다.
- 입장을 완료한 직후와 이어하기에서 MapController가 위 함수를 연결합니다. 노드 완료 콜백은 거래 Action과 분리하여 완료가 확정된 뒤 호출합니다.

게임 진행 중 생성·강화하는 카드도 저장 카탈로그에서 찾을 수 있는 에셋 ID가 필요합니다. 카드 이름이나 실행 중 InstanceID는 저장 키로 사용하지 않습니다.

## 에셋 목록과 검증

`Assets/Resources/RunAssetCatalog.asset`은 에셋 GUID와 로컬 ID를 런·카드·덱·유물·전투·노드 데이터 참조에 연결합니다. 관련 `.asset` 변경 시 목록을 갱신하며 빌드 전에도 갱신합니다. 수동 메뉴는 `ProjectDN/Refresh Run Save Catalog`입니다. `ProjectDN/Setup Run Checkpoints`는 기존 타이틀·전투 씬에 버튼과 문구를 연결합니다.

테스트 실행에서는 `PROJECTDN_RUN_SAVE_PATH`로 `.utmp/run-save` 아래 별도 파일을 사용하여 실제 사용자 저장 파일에 접근하지 않습니다.
