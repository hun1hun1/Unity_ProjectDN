# 전투 보상

적 사망으로 전투에서 승리하면 중앙에 골드, 카드 보상, 남은 보상 건너뛰기 목록이 표시됩니다. 패배하거나 인자 없는 `EndBattle()`로 전투를 중단하면 보상은 생성되지 않습니다.

- 현재 1층 런 전투의 골드 보상은 **노드 시드로 정한 20~25 + 현재 노드 번호(1부터 시작)**입니다. 다른 층의 런 전투는 조우 에셋의 `goldReward`를 사용하며, BattleScene 단독 실행의 기본값은 `BattleRewardSystem`의 `Gold Reward`에 설정된 20입니다.
- 골드를 누르면 한 번만 지급되며 해당 항목이 사라집니다.
- 카드 보상을 누르면 꿈 / 악몽 / 카드 보상 건너뛰기가 표시됩니다.
- 꿈은 서로 다른 카드 3장, 악몽은 서로 다른 카드 2장 중 한 장을 선택합니다.
- 꿈이나 악몽을 선택한 뒤에는 재추첨하거나 건너뛸 수 없습니다.
- 카드를 클릭하면 초록색 테두리로 선택을 표시합니다. 다른 카드를 누르면 선택이 이동하며, 클릭만으로 지급되지는 않습니다.
- 카드 목록 아래 중앙의 확인 버튼을 눌러야 선택한 카드가 해당 런의 덱에 추가됩니다. 선택 전에는 확인 버튼이 비활성화되며, 이미 가진 카드도 받을 수 있습니다.
- 보상 목록의 건너뛰기는 아직 받지 않은 골드와 카드를 포기합니다. 카드 선택 중에는 사용할 수 없습니다.
- 모든 항목을 수령하거나 포기한 뒤 완료 버튼을 누르면 보상창을 닫습니다.

1층 엘리트는 전투 보상 처리를 마칠 때 공용 `Elite Victory Conduits`에서 매개체를 뽑아 지급합니다. 일반 70%, 고급 30%로 등급을 정하고, 해당 등급의 남은 후보를 균등 추첨합니다. 같은 런에서 이미 보유했거나 앞선 1층 노드에서 제시된 매개체는 제외합니다. 7번 노드 전용인 두 매개체도 무작위 후보에서 제외합니다. 한 등급이 소진되면 다른 등급을 사용하고, 양쪽 모두 소진됐으면 매개체 보상 없이 노드를 완료합니다.

골드·카드를 건너뛰어도 엘리트 매개체를 지급하며, 지급과 다음 노드 진행을 함께 저장합니다. 6번 엘리트 승리 시 7번 매개체 노드에서는 별도로 고급 확장 탄창을 제시합니다. 현재 공용 풀에 일반·고급 확장 탄창 예시를 세 개씩 등록했으며 효과는 모두 최대 탄약 +1입니다. [매개체 노드](MapSystem.md#매개체-노드) · [체크포인트](RunCheckpoints.md#1층-조우와-매개체-복원)

## 보상 화면

보상 요약(`SummaryPanel`), 덱 선택(`DeckSelectPanel`), 카드 선택(`CardRewardPanel`)은 `Assets/Images/UI/Rewards/battle-reward-panel.png`를 9슬라이스로 공유합니다. 보상 화면 뒤의 전투 영역은 어둡게 처리합니다.

덱 선택의 꿈·악몽·카드 보상 건너뛰기 버튼은 같은 폴더의 `reward-deck-*.png`를 사용합니다. 꿈·악몽은 같은 비율을 유지하고 문구를 문양 오른쪽에 표시합니다. 건너뛰기는 하단 중앙에 배치합니다. 버튼 상태 전환과 클릭 연결은 씬의 `Button`에서 관리합니다.

보상 카드에 마우스를 올리면 본문이 화면 환산 크기 16에 도달하도록 필요한 호버 배율을 계산합니다. 확인 버튼 위쪽을 표시 영역으로 사용하고, 이 영역에 들어오는 크기로 제한해 버튼을 가리지 않도록 합니다. 일반 카드 설명의 수치는 기존 보상 표시 규칙을 따릅니다. 공통 확대 방식은 [손패와 목록의 호버](CardHandLayout.md)에 있습니다.

## 데이터베이스와 확률

`CardRewardSystem`과 상점이 공유하는 `Assets/CardDatabase/Soldier/BattleRewardPools.asset`에 꿈과 악몽별 7개 데이터베이스가 연결되어 있습니다. 아래 가중치는 전투 보상에 적용됩니다. [상점의 슬롯별 확률](MapSystem.md#상점-카드-진열)은 같은 후보 데이터베이스에서 분류를 별도로 균등 추첨하므로 전투 보상 가중치와 구분합니다.

| 분류 | 가중치 |
|---|---:|
| 일반 공격 | 30 |
| 일반 스킬 | 30 |
| 고급 공격 | 15 |
| 고급 스킬 | 15 |
| 희귀 공격 | 3 |
| 희귀 스킬 | 3 |
| 희귀 지속 | 4 |

각 선택지를 추첨할 때 남아 있는 분류 가중치로 분류를 선택하고, 그 안에서 카드를 균등하게 선택합니다. 이미 나온 카드는 이후 선택지 후보에서 제외합니다. 데이터베이스 자체는 수정하지 않습니다. 빈 분류와 가중치 0인 분류는 제외하고 나머지 가중치를 재분배합니다. 등록된 카드의 덱/종류/희귀도가 분류와 다르면 후보에서 제외합니다.

꿈 전체 후보가 3장 미만이거나 악몽 전체 후보가 2장 미만이면 해당 덱 버튼을 비활성화합니다. 현재 실제 악몽 보상 DB가 비어 있으므로 비활성화되며, 테스트용 카드를 실제 DB에 넣지는 않았습니다. 확률 및 상태 테스트는 각 분류에 서로 다른 후보 3장을 생성합니다.

## 상태와 연결

- `BattleManager.Result`와 `BattleEnded`가 승리/패배/중단을 구분합니다.
- `BattleRewardSystem`이 수령 여부와 Summary → DeckChoice → CardChoice 흐름을 관리합니다.
- `CardRewardUI`가 상태에 맞는 화면과 버튼을 표시합니다. 보상 카드 설명은 원본 수치로 표시합니다.
- `RunGoldInventory.Gold`는 씬 전환과 체크포인트 복원 시 유지됩니다. 새 런은 기존 골드를 초기화하고 `RunDefinition.startingGold`를 지급합니다. 현재 `FirstFloorRun`의 시작 골드는 100입니다.
- 런의 보상 완료는 `RunBattleBridge`를 거쳐 현재 노드를 완료하고 MapScene으로 돌아갑니다. 보상 수령이나 완료를 저장하지 못하면 마지막 체크포인트 상태로 되돌아가 다시 시도할 수 있습니다. [노드 체크포인트와 이어서 하기](RunCheckpoints.md) 참고.
- `BattleRewardAssetSetup.CreateAssets()`는 현재 BattleScene에 보상 UI와 14개 DB 참조를 구성한 에디터 도구입니다. 메뉴: ProjectDN → Setup Battle Rewards. 재실행 시 보상 UI와 기본 골드 값을 다시 구성하고, 공유 풀 설정은 유지합니다.

## 검증

2026-11-17 Unity 6000.0.85f2에서 공용 엘리트 보상의 일반·고급 추첨과 보유 매개체 제외, 완료 체크포인트의 단일 지급 검사 3/3이 통과했습니다. 결과는 로컬 `.utmp/elite-conduits-verify.xml`에 있습니다. 해당 변경의 대상 재검사이며 전체 EditMode와 독립 실행 빌드 검증은 남아 있습니다.

2026-11-08 Unity 6000.0.85f2에서 공유 풀 연결 뒤 전투 보상·상점 관련 테스트 43/43이 통과했습니다. 전투 보상 카드의 선택·확정, 상점의 빈 악몽 슬롯과 분류별 추첨을 포함합니다. 결과는 로컬 `.utmp/shop-stock-verified.xml`에 있습니다.

2026-11-05 Unity 6000.0.85f2에서 보상 카드의 호버·선택 초기화·중복 확정 방지와 720p의 본문 가독성·확인 버튼 노출을 검사했습니다. 이를 포함한 최종 관련 검사 18/18이 통과했습니다. 결과는 로컬 `.utmp/readable-card-hover/regression-final.xml`, 보상 화면은 `RewardCard-1280x720.png`에 있습니다. 최종 코드의 전체 재검사는 사용자 요청으로 중단했습니다.

2026-11-03에는 보상 패널과 버튼을 적용한 뒤 Unity 6000.0.77f1에서 세 화면의 렌더링, 골드 수령, 꿈·악몽 선택, 건너뛰기와 카드 확정을 확인했습니다. 악몽 클릭 검증에는 테스트 내부의 후보 카드 두 장을 사용했습니다.

최초 구현 검증 기록: Unity 6000.0.77f1 전체 테스트 309개 실행 중 307개 통과. 발견된 기존 EndBattle 반사 호출 충돌과 새 보상 카드의 소멸 설정을 금지하던 테스트를 수정한 뒤, 영향 범위의 41개 테스트를 다시 실행하여 모두 통과했습니다. 결과: `.utmp/rewards-full.xml`, `.utmp/rewards-regression.xml`. 자동 테스트에서 실제 씬의 승리/패배와 보상 버튼 연결을 검증했으며, 이 최초 검증에서는 화면 외형의 수동 검수를 수행하지 않았습니다.
