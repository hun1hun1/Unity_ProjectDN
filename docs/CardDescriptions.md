# 카드 설명의 전투 미리보기

`CardData.description`은 설명 템플릿이며, 손패의 `CardUI`와 카드 목록의 `DeckCardUI`가 `CardDescriptionBuilder`로 표시할 문자열을 만듭니다. 원본 카드·효과 에셋은 실행 중 변경하지 않습니다. 자리표시자가 없는 설명은 그대로 표시합니다.

| 자리표시자 | 의미 |
|---|---|
| `{damage:0}` | `effects[0]`인 DamageEffect의 상태이상 보정 후 피해 |
| `{damage:2.0}` | `effects[2]`인 총알 조건부 효과의 `bonusEffects[0]` 피해 |
| `{ammoCost:2}` | `effects[2]`인 총알 조건부 효과의 소모량 |
| `{ammoCondition:2}` | 현재 발동 가능 또는 현재 총알 부족 |

인덱스는 0부터 시작합니다. 효과 순서를 변경하면 연결된 자리표시자도 함께 수정해야 합니다. 존재하지 않는 효과 경로나 지원하지 않는 자리표시자는 그대로 남습니다.

예를 들어 저격은 다음 설명을 사용합니다.

```text
적에게 {damage:0}의 피해를 줍니다.
총알이 {ammoCost:2}알 이상이면 {ammoCost:2}알을 소모하여
추가로 적에게 {damage:2.0}의 피해를 줍니다.
{ammoCondition:2}
```

피해량은 실제 전투와 같은 DamageCalculator의 배율과 정수 처리 규칙을 사용합니다. 플레이어의 녹슬음과 해당 대상의 약점 노출을 적용하며, 자해는 플레이어를 공격자와 방어자로 사용합니다. 숫자는 방어도 차감 전 피해입니다. 원본보다 감소하면 붉은색, 증가하면 녹색으로 표시합니다.

플레이어·적의 상태 변경과 플레이어의 총알 변경 이벤트를 구독하여 설명을 갱신합니다. 카드가 비활성화·파괴되거나 다시 연결되면 기존 구독을 해제하고, 활성화될 때 현재 상태를 다시 표시합니다. 카드 목록에는 해당 손패의 전투 문맥을 전달합니다. 전투 문맥 없는 카드 목록·보상 표시는 기본 피해를 사용하며 현재 총알 판정 문구는 표시하지 않습니다.

미리보기는 상태이상·잔탄·최대 총알을 복사하고, 카드 필수 총알 소모 후 효과를 실제 순서대로 처리합니다. 상태 부여·장전·최대 총알 증가·조건부 소모는 이 복사본에만 반영합니다. 실제 Execute, TrySpend, Load를 호출하지 않습니다.

카드를 사용하면 실제 총알 소모 전에 설명 갱신을 중단하여 사용 애니메이션 동안 실행 시점의 값을 유지합니다. 사용에 실패하면 현재 상태로 갱신을 재개합니다. 남은 손패와 열린 카드 목록은 계속 갱신됩니다.

총알이 부족한 추가 효과도 보정된 피해량을 보여줍니다. 그 분기의 상태 변화는 별도 복사본에만 적용하므로 뒤의 실제 발동 가능한 효과에 영향을 주지 않습니다. 여러 타격의 정수 처리는 타격별로 수행합니다. 녹슬음과 약점 노출이 모두 있을 때 저격은 기본 4와 추가 6으로, 두 값을 합쳐 보정한 11이 아닙니다.

새 효과가 뒤의 피해 계산에 영향을 주는 경우에는 CardEffect.Preview도 구현해야 합니다. Preview의 기본 구현은 전투 미리보기에 영향을 주지 않습니다. 현재 미리보기는 HP 손실, 사망 및 방어도 소모를 시뮬레이션하지 않습니다.

`CardDescriptionTests`는 피해·자해 보정, 상태 적용·만료, 총알 조건과 효과 순서, 공유 에셋 및 실제 전투 상태 보존, 비활성화·재연결, 실제 BattleScene의 꿈·악몽 손패와 열린 카드 목록 갱신을 검사합니다.

손패 카드의 상태이상 설명은 `CardHoverUI`의 `tooltipDelay`(기본 1초) 뒤에 표시됩니다. 확대와 화면 경계 보정을 마친 카드의 오른쪽 공간을 우선 사용하고, 부족하면 왼쪽에 배치합니다. 포인터 이탈·드래그·사용·비활성화·카드 재설정은 패널을 닫고 대기 시간을 초기화합니다. 시간 정지 중에도 지연 판정은 진행됩니다.

`CardStatusCollector`는 `CardEffect.CollectReferencedStatuses`를 통해 설명할 상태이상을 수집합니다. `ApplyStatusEffect`와 총알 조건부 효과의 내부 효과를 지원하며, 같은 상태이상 타입은 한 번만 표시하고 순환 참조를 건너뜁니다. 새 효과가 상태이상을 참조하면 이 조회 함수도 구현해야 합니다. 이 과정은 실제 효과를 실행하지 않습니다. 카드용 패널은 상태이상 정의의 이름·설명을 표시하며, 현재 캐릭터에 적용된 상태의 남은 턴은 표시하지 않습니다.
손패의 `CardUI`와 네 종류의 드로우·버림 더미 목록의 `DeckCardUI`를 우클릭하면 공통 `CardInspectionUI`를 엽니다. 원본 카드는 이동하지 않고, 표시용 `DeckCardUI`에 같은 데이터와 전투 문맥을 연결합니다. 우클릭 창의 피해량은 상태이상 보정 전의 기본 수치로 표시합니다. 현재 적용된 상태와 카드 효과가 앞서 부여하는 상태 모두 피해량에 반영하지 않으며, 자해와 총알 조건부 추가 피해도 기본 수치를 사용합니다. 현재 총알에 따른 발동 가능 안내는 유지하고 상태이상 이름·설명은 조건부 효과까지 수집하여 즉시 표시합니다. 손패와 카드 더미의 일반 설명은 기존 전투 미리보기를 유지합니다. 상태이상과 소멸 설명이 모두 없는 카드는 추가 설명 패널을 숨깁니다.

표시용 카드 안쪽을 클릭하면 창을 유지하고, 나머지 영역(상태 설명 포함)을 클릭하면 닫습니다. 창이 열린 동안 카드 사용·드래그·호버·턴 종료·카드 더미와 보상 입력을 차단하고 기존 버튼 선택을 해제합니다. 닫기 클릭이 뒤의 UI 동작으로 이어지지 않도록 닫힌 프레임까지 잠금을 유지한 뒤 이전 버튼 활성 상태와 선택을 복원합니다. 창을 비활성화하거나 파괴해도 입력 잠금은 해제됩니다. 시간 배율은 변경하지 않습니다.

전투 중 카드 검사 창은 플레이어 턴에만 열리며, 효과 실행·카드 사용·드래그·드로우·복귀 애니메이션 중에는 열리지 않습니다. 코스트나 총알이 부족해 사용할 수 없는 카드도 검사할 수 있습니다. `Assets/Prefabs/UI/CardInspection.prefab`에서 `preferredCardHeight`, `statusWidth`, `cardGap`, `screenMargin`, `statusPadding`, `sortingOrder`를 조절할 수 있습니다. 카드는 중앙을 유지하고 상태 설명은 오른쪽에 배치하며, 화면이 좁으면 카드 아래로 옮깁니다.

`CardInspectionTests`는 손패·네 카드 더미의 우클릭, 즉시 표시와 중복 상태 제거, 원본 카드·전투 상태 보존, 실제 UI 레이캐스트와 카드/배경 클릭, 입력 차단·복원, 해상도 변경, 비활성화 정리, 처리 중 열기 제한, 프리팹 생성 후 실제 카드 그래픽의 배율·크기를 검증합니다.

맵의 전체 덱 목록에서도 같은 상세창을 엽니다. 손패 호버와 전투·맵의 우클릭 상세창은 `CardStatusDescriptionBuilder`에서 같은 상태이상·소멸 설명을 가져옵니다.

## 공용 상태 설명 프레임

상태 아이콘 툴팁(`StatusTooltip`), 손패 카드 호버 툴팁(`CardStatusTooltip`), 우클릭 상세창의 `StatusDescriptions`에 `Assets/Images/UI/Tooltips/card-status-tooltip-frame.png`를 적용했습니다. 세 곳 모두 남청색 바탕과 얇은 은회색 9슬라이스 테두리를 사용하고, 우클릭 상태 설명의 본문도 흰색으로 맞췄습니다. 프레임 이미지는 포인터 입력을 가로채지 않습니다.

2026-11-03 Unity 6000.0.77f1에서 렌더링과 호버·상세보기, 입력 복원, 맵 덱 상세보기를 포함한 관련 테스트 13개가 통과했습니다.

## 설명 글꼴과 검증

현재 카드·덱 카드와 상태·카드 상태·더미 툴팁의 설명은 `NotoSansKR-Bold SDF`를 사용합니다. `NotoSansKR-Bold SDF`와 `NotoSansKR-VF SDF`는 모두 2048×2048 정적 아틀라스로 저장되어 있습니다. Multi Atlas 설정이 켜져 있어도 정적 모드에서는 미포함 글자가 실행 중 자동으로 추가되지 않습니다.

`TooltipFontTests`는 프리팹의 설명 글꼴 연결, 저장된 아틀라스, 현재 카드·상태 설명의 대체 문자 없는 렌더링을 검사합니다. 동적 아틀라스 용량 회귀 검증은 에디터의 원본 Font 에셋으로 별도 동적 글꼴을 만들어 실행하며, 저장된 정적 글꼴의 모드나 아틀라스는 변경하지 않습니다.
