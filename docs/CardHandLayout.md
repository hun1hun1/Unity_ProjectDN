# 꿈·악몽 손패 크기

BattleScene의 두 손패 컨테이너는 부모 영역 전체를 사용하는 Stretch 앵커를 유지합니다. HorizontalLayoutGroup은 카드 크기를 직접 제어하지 않으며, 현재 위쪽 여백은 40, 아래쪽 여백은 4입니다.

`CardHandController.RefreshCardSizes()`는 컨테이너 높이에서 레이아웃의 세로 여백을 뺀 값을 시작 카드 프리팹의 높이와 비교합니다. 카드가 들어갈 공간이 부족하면 원본 가로·세로 비율을 유지하여 줄이고, 공간이 충분하면 원본 크기로 복원합니다. 원본 크기보다 크게 확대하지 않습니다.

`CardUI.ResizeForHand()`는 처음 저장한 카드 루트 크기와 모든 TMP 글꼴 크기를 기준으로 계산합니다. 현재 Card.prefab의 원본 크기는 200×260입니다. 카드 그림의 Stretch 영역과 글꼴이 같은 비율로 줄어들며, 프리팹 에셋 자체는 변경하지 않습니다.

| 화면 비율을 반영한 Canvas 크기 | 손패 높이 | 카드 크기 |
|---|---:|---:|
| 1920×1080 | 270 | 약 173.8×226 |
| 1920×810 (2560×1080 화면) | 202.5 | 약 121.9×158.5 |
| 1920×540 (3840×1080 화면) | 135 | 70×91 |

표의 수치는 현재 가로 기준 CanvasScaler를 적용한 내부 UI 단위입니다.

새 카드가 추가되면 드로우 애니메이션 전에 크기를 적용합니다. 손패 영역 크기가 바뀌면 다음 LateUpdate에서 기존 카드에도 적용합니다. 드래그 또는 사용·버림 애니메이션으로 손패에서 분리된 카드는 도중에 크기를 바꾸지 않습니다. 취소된 드래그가 손패로 돌아오면 현재 손패 크기에 다시 맞춥니다.

CardVisual의 애니메이션 배율은 별도로 유지합니다. 이번 수정은 손패 높이에 대한 대응이며, 최대 패 개수 증가에 따른 가로 배치 규칙과 전체 CanvasScaler 설정은 변경하지 않습니다.

손패 카드에 마우스를 올리면 `CardHoverUI`가 `HoverVisual`을 확대하고, 포인터를 치우면 원래 크기로 돌립니다. 현재 프리팹의 1.5배는 기본 배율이며, `CardHoverSizing`이 화면에 투영한 본문 크기가 16에 도달하도록 필요한 추가 배율을 계산합니다. 낮은 해상도에서는 더 많이 확대됩니다. 현재 본문 크기 11과 카드 비율에서는 호버 카드 높이가 약 378픽셀에 해당합니다. 고해상도에서 기본 배율이 더 큰 표시를 만들면 그 배율을 사용합니다.

카드 전체가 화면에 들어오도록 가로·세로 크기를 계산해 확대 상한을 둡니다. 화면이 작아 목표 글자 크기를 확보할 수 없는 경우 화면 안에 들어오는 크기를 사용합니다. 전환 시간은 기본 0.12초이며 `Card.prefab`의 해당 컴포넌트에서 수정할 수 있습니다. 확대는 기존 HoverVisual에 적용하고 화면 경계에서는 위치를 보정합니다. 기준 글꼴 크기와 루트 카드 크기는 기존 손패 크기 계산에서 관리합니다.

같은 계산을 `DeckCardHoverUI`에도 적용합니다. 덱·카드 더미 목록과 DeckCard 프리팹을 사용하는 보상 카드의 기본 호버 배율은 1.3배이며, 본문 가독성에 필요한 추가 배율을 같은 방법으로 계산합니다. 우클릭 상세보기는 기존 상세보기 레이아웃을 사용합니다.

상점 진열 카드도 `DeckCard` 프리팹의 호버 확대를 사용합니다. 진열 카드의 상세보기는 좌클릭으로 열며, 덱·더미 목록에서는 우클릭으로 엽니다. [상점 진열과 조작](MapSystem.md#상점-카드-진열)에 연결과 검증을 정리했습니다.

보상 카드의 호버는 확인 버튼 위쪽을 표시 영역으로 사용합니다. 작은 화면에서는 이 영역에 들어오는 크기로 제한하고, 확대된 카드가 확인 버튼을 가리지 않도록 위치를 보정합니다.

프리팹 구조는 `Card → HoverVisual → CardVisual`입니다. Card 루트의 투명 Image가 원래 카드 영역에서 포인터 입력을 받고, 표시용 이미지와 텍스트는 입력을 받지 않습니다. HoverVisual의 Canvas 정렬만 조절하므로 손패의 카드 순서와 레이아웃 간격은 유지됩니다.

드로우·드래그·사용·버림·복귀 중에는 마우스 확대를 차단하고, 해당 동작 시작 및 카드 비활성화 시 확대 크기와 위치를 초기화합니다. 현재 프리팹의 드래그 확대 1.5배는 기존 CardVisual에 적용되므로 마우스 확대와 중복되지 않습니다.

`HandLayoutTests`는 실제 BattleScene을 Play Mode로 불러와 논리적인 Canvas 크기를 바꾸며 두 손패의 카드 경계, 모든 글꼴 비율, 신규 드로우, 원본 크기 복원, 드래그 복귀, 사용·버림 애니메이션을 검증합니다. 이 테스트는 화면 캡처를 통한 가독성 검증을 대신하지 않습니다.

`CardHoverTests`는 양쪽 손패의 포인터 판정, 확대·복원, 카드 순서와 글꼴 유지, 넓은 Canvas의 네 모서리 배치, 드래그·복귀·드로우·사용·버림 및 비활성화와의 연동을 검사합니다.
## 드로우·버림 더미의 카드 목록

꿈·악몽의 DrawPile과 DiscardPile 버튼은 해당 `CardHandController`를 목록에 전달해 전투 미리보기 문맥을 연결합니다. `DeckListUI`는 DeckCard 프리팹 크기에 독립적인 `Card Scale`을 적용해 GridLayoutGroup의 셀을 계산합니다. 현재 기본 크기는 200×260입니다. 전체 덱 목록은 가용 폭에 따라 열 수를 조절합니다.

`DeckCardUI.ResizeForList()`는 원본 글꼴 크기에 비율을 적용하고, 카드 간격도 같은 비율로 조절합니다. 반복해서 목록을 열거나 화면 크기를 바꿔도 글자가 누적해서 줄어들지 않습니다. 카드 목록의 셔플은 복사본에만 적용하므로 실제 드로우·버림 더미의 내용과 순서는 유지됩니다.

`DeckListLayoutTests`는 실제 BattleScene의 네 버튼, 세 가지 Canvas 높이, 빈 손패, 열린 목록의 크기 변경과 같은 프레임의 반복 열기를 검사합니다.

## 호버 가독성 검증

`ReadableCardHoverTests`는 실제 전투 씬과 카드 프리팹을 사용해 1280×720, 1600×900, 1920×1080 렌더링 크기에서 호버 본문의 화면 환산 크기를 측정합니다. 호버 중 해상도 변경, 기존 확대 배율의 적용, 작은 화면에서의 크기 상한, 루트·글꼴·카드 순서와 호버 해제 상태를 함께 검사합니다. 현재 CardData 전체의 설명이 기본 본문 영역에 들어오는지도 측정합니다.

2026-11-05 Unity 6000.0.85f2에서 초기 관련 테스트 22/22가 통과했습니다. 이후 보상 확인 버튼을 보호하는 보정을 적용한 최종 관련 검사 18/18도 통과했습니다. 최종 검사에는 손패·카드 더미·전체 덱·보상 카드의 호버, 본문 넘침, 720p 보상 확인 버튼 노출이 포함됩니다. 720p·900p·1080p 손패·목록 렌더링 6장과 720p 보상 화면을 확인했습니다.

최초 전체 EditMode 검사는 527건 중 525건이 통과했고, 보상 카드와 전체 덱의 고정 1.3배 기대값 2건이 실패했습니다. 기대값 갱신과 보상 호버 영역 보정 후 해당 검사는 최종 관련 검사에서 통과했습니다. 최종 코드의 전체 재검사는 사용자 요청으로 중단했습니다. 완료된 최종 전체 결과는 없습니다. 결과·로그·렌더링은 로컬 `.utmp/readable-card-hover/`에 있으며, 세부 기록은 [구현 계획](superpowers/plans/2026-11-05-readable-card-hover.md)에 있습니다.
